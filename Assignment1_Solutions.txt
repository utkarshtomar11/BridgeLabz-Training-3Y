Q1. Difference between Frontend, Backend, and Full-Stack Development
--------------------------------------------------------------------------------
FRONTEND DEVELOPMENT
- The part of a website/app that users see and interact with directly (the
  "client side").
- Built using HTML (structure), CSS (styling), and JavaScript (interactivity),
  along with frameworks like React, Angular, or Vue.
- Responsible for layout, design, buttons, forms, animations, and overall
  user experience (UX).
- Example: The product listing page, shopping cart icon, and checkout button
  design on Amazon.com are all frontend work.

BACKEND DEVELOPMENT
- The "server side" of an application - the part users don't see.
- Handles business logic, database operations, authentication, and server
  configuration.
- Built using languages/frameworks like Node.js, Python (Django/Flask), Java
  (Spring), PHP, or Ruby on Rails, along with databases like MySQL or MongoDB.
- Example: When you log in to Amazon, the backend verifies your username and
  password against the database and manages your session.

FULL-STACK DEVELOPMENT
- Involves working on BOTH frontend and backend of an application.
- A full-stack developer can build the complete product - from the user
  interface to the server logic and database.
- Example: A single developer building an entire e-commerce website (product
  pages + payment processing + database) using the MERN stack
  (MongoDB, Express, React, Node.js) is doing full-stack development.

Real-world analogy: Think of a restaurant.
- Frontend = the dining area, menu, and waiter (what the customer sees/uses).
- Backend = the kitchen, chef, and inventory system (works behind the scenes).
- Full-stack = a person who can both wait tables AND cook in the kitchen.

--------------------------------------------------------------------------------

                                                             v

                                                      |    DATABASE    |
                                                      | (stores/returns|
                                                      |     data)      |
                                                      +----------------+

Explanation:
1. The CLIENT (web browser or mobile app) sends a request to the SERVER,
   usually by the user typing a URL or clicking a link/button.
2. The SERVER receives the request, processes it (may query the DATABASE
   for data), and prepares a response.
3. The SERVER sends the response back to the CLIENT (HTML page, JSON data,
   images, etc.).
4. The CLIENT renders/displays this response to the user.
This request-response cycle repeats every time the user interacts with the
website.


Q3. How a Browser Requests and Displays a Web Page
--------------------------------------------------------------------------------
Step 1: URL Entry
  The user types a URL (e.g., www.example.com) into the browser's address
  bar or clicks a link.

Step 2: DNS Resolution
  The browser contacts a DNS (Domain Name System) server to translate the
  human-readable domain name into an IP address (e.g., 93.184.216.34).

Step 3: Establishing Connection
  The browser opens a TCP connection to the server at that IP address
  (usually over port 80 for HTTP or port 443 for HTTPS), and performs a
  TLS/SSL handshake if HTTPS is used.

Step 4: Sending HTTP Request
  The browser sends an HTTP GET request to the server, asking for the
  specific page/resource.

Step 5: Server Processing
  The web server receives the request, processes it (may run backend code,
  query a database), and prepares an HTTP response containing the
  requested HTML document (and status code, e.g., 200 OK).

Step 6: Receiving the Response
  The browser receives the HTML file along with linked resources such as
  CSS stylesheets, JavaScript files, images, and fonts (each fetched with
  its own request if not already cached).

Step 7: Parsing and Rendering
  - The browser parses the HTML to build the DOM (Document Object Model).
  - It parses CSS to build the CSSOM (CSS Object Model).
  - It combines DOM + CSSOM into a Render Tree.
  - The browser calculates layout (position/size of elements) and then
    paints pixels on the screen.
  - JavaScript is executed, which may further modify the DOM (dynamic
    content).

Step 8: Display
  The final web page is displayed to the user in the browser window,
  fully interactive.


Q4. Tools Required to Set Up a Web Development Environment
--------------------------------------------------------------------------------
1. Code Editor / IDE (e.g., VS Code, Sublime Text)
   Purpose: Write and edit HTML, CSS, JavaScript, and other code with
   features like syntax highlighting, autocomplete, and debugging.

2. Web Browser (e.g., Google Chrome, Firefox)
   Purpose: Run and preview the website; browser Developer Tools help
   inspect elements, debug JavaScript, and test responsiveness.

3. Version Control System (e.g., Git)
   Purpose: Track changes to code over time and enable collaboration with
   other developers.

4. Code Hosting Platform (e.g., GitHub, GitLab)
   Purpose: Store code remotely, manage repositories, and collaborate on
   projects.

5. Package Manager (e.g., npm, yarn)
   Purpose: Install, manage, and update third-party libraries and
   dependencies used in a project.

6. Local/Development Server (e.g., Live Server extension, XAMPP, Node.js
   http-server)
   Purpose: Serve the website locally so it can be tested in a real
   browser environment before deployment.

7. Browser Developer Tools (built into browsers)
   Purpose: Inspect HTML/CSS, debug JavaScript, monitor network requests,
   and test performance.

8. Database Software (e.g., MySQL, MongoDB) - for full-stack projects
   Purpose: Store and manage application data.

9. Terminal / Command Line
   Purpose: Run commands for Git, npm, servers, and build tools.

10. Design/Prototyping Tools (e.g., Figma) - optional
    Purpose: Design the layout and UI before coding it.


Q5. What is a Web Server? Examples of Commonly Used Servers
--------------------------------------------------------------------------------
Definition:
A web server is software (often running on dedicated hardware) that stores,
processes, and delivers web pages and other content to clients (browsers)
over the internet using the HTTP/HTTPS protocol. It listens for incoming
requests and responds with the requested resources (HTML pages, images,
JSON data, etc.).

Commonly Used Web Servers:
1. Apache HTTP Server - One of the oldest and most widely used open-source
   web servers, known for flexibility and a large module ecosystem.
2. Nginx - Known for high performance, handling many concurrent
   connections efficiently; also used as a reverse proxy and load balancer.
3. Microsoft IIS (Internet Information Services) - Windows-based web
   server, commonly used for hosting ASP.NET applications.
4. Node.js (with Express) - A JavaScript runtime that can act as a
   lightweight web server, popular for building APIs and full-stack apps.
5. LiteSpeed - A high-performance commercial web server compatible with
   Apache configurations.


Q6. Roles of Frontend Developer, Backend Developer, and Database Administrator
--------------------------------------------------------------------------------
FRONTEND DEVELOPER
- Designs and implements the user interface (UI) and user experience (UX).
- Writes HTML, CSS, and JavaScript; works with frameworks like React or
  Angular.
- Ensures the website is responsive, accessible, and visually consistent
  across devices and browsers.
- Communicates with backend developers to integrate APIs into the UI.

BACKEND DEVELOPER
- Builds and maintains the server-side logic of the application.
- Writes APIs, handles authentication/authorization, business logic, and
  server configuration.
- Connects the application to the database and ensures data is processed
  and returned correctly.
- Focuses on performance, security, and scalability of the server.

DATABASE ADMINISTRATOR (DBA)
- Designs, implements, and maintains the database structure (schemas,
  tables, relationships).
- Ensures data integrity, security, and backup/recovery procedures.
- Optimizes database performance (indexing, query tuning).
- Manages user access and permissions to the database.
- Monitors database health and handles scaling as data grows.

Together, these three roles collaborate: the frontend developer builds
what the user sees, the backend developer builds the logic that powers
it, and the DBA ensures the data behind it all is stored safely and
efficiently.

Q8. Difference Between Static and Dynamic Websites
--------------------------------------------------------------------------------
STATIC WEBSITES
- Content is fixed and does not change unless a developer manually edits
  the code.
- Built using only HTML and CSS (sometimes JavaScript for minor
  interactivity, but no server-side processing of data).
- Same content is shown to every visitor.
- Faster to load, simpler to host, and cheaper to build.
- Example: A personal portfolio website or a simple business "brochure"
  site with an About page and Contact page that never changes.

DYNAMIC WEBSITES
- Content changes based on user interaction, input, or data stored in a
  database; generated in real time.
- Uses server-side languages (PHP, Python, Node.js, etc.) and databases
  along with HTML/CSS/JS.
- Different content can be shown to different users (e.g., personalized
  dashboards, login-based content).
- More complex to build and host, but far more flexible.
- Example: An e-commerce website like Amazon, where product listings,
  prices, and recommendations change based on the user, inventory, and
  database content.

Key difference in one line: Static = same content for everyone, fixed
files; Dynamic = content generated on the fly using a database/server
logic, personalized per user.


Q9. Five Web Browsers and Their Rendering Engines
--------------------------------------------------------------------------------
1. Google Chrome - Uses the "Blink" rendering engine (a fork of WebKit),
   with the V8 JavaScript engine. Known for speed and wide extension
   support.

2. Mozilla Firefox - Uses the "Gecko" rendering engine, with
   SpiderMonkey as its JavaScript engine. Known for strong privacy
   features and open-source development.

3. Safari - Uses the "WebKit" rendering engine, developed by Apple, with
   the JavaScriptCore engine. Default browser on macOS/iOS, optimized for
   Apple hardware.

4. Microsoft Edge - Currently uses "Blink" (since Edge switched to the
   Chromium engine in 2020), with the V8 JavaScript engine. Default
   browser on Windows.

5. Opera - Also uses "Blink" (Chromium-based) with the V8 JavaScript
   engine, but adds extra features like a built-in VPN and ad blocker.

How Rendering Engines Differ:
- Blink (Chrome, Edge, Opera) and WebKit (Safari) share a common
  ancestry but have since diverged; Blink tends to adopt new web
  standards/features faster and is optimized differently for
  performance.
- Gecko (Firefox) is an independent engine developed separately from
  WebKit/Blink, sometimes leading to minor differences in how CSS
  features or JavaScript APIs are supported or rendered (e.g., subtle
  differences in font rendering, CSS Grid quirks, or scrollbar styling).
- Because of these differences, developers must test websites across
  multiple browsers/engines (cross-browser testing) to ensure consistent
  appearance and behavior for all users.

Flow Explanation:
1. CLIENT (browser) sends an HTTP request to the SERVER (e.g., requesting
   a webpage or triggering an action like "Add to Cart").
2. The SERVER, through its API layer, processes the request and queries
   the DATABASE if data is needed (e.g., fetching product details).
3. The DATABASE returns the requested data (or confirms an update) back
   to the API/server layer.
4. The SERVER sends an HTTP response back to the CLIENT - this could be
   a full HTML page, or JSON data (for APIs used by single-page apps),
   which the browser then renders/displays to the user.

This client -> server -> API -> database -> server -> client cycle forms
the backbone of nearly all modern web applications.
